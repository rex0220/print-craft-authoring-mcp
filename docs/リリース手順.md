## 1. 版を決める

- semver。0.x の間は、利用者に見える変更（ツールの入出力、設定項目、資料）で minor、直しで patch
- 版を書く場所（すべて同じ版に）:
  - `package.json` と `package-lock.json`: `npm version <版> --no-git-tag-version`
  - `compat.json` の `mcpVersion`
  - `.claude-plugin/plugin.json` の `version`（Claude Code は、この版が変わったときだけ新しい版を利用者に届ける）
  - README の確かめの表の、期待の版
- 中核（tools）を新しくするときは、**先に tools を公開する**（print-craft-authoring の main に入れて push → Takashi が `npm publish` → 公開版で `version --expect 7` が一致）。そのあと MCP で `npm install --save-dev --save-exact @rex0220/print-craft-authoring-tools@<版>`、`compat.json` の `coreVersion` の下限を合わせる
- `CHANGELOG.md` に版の節を書く

## 2. まっさらな checkout から作って確かめる

作業中のフォルダーで作らない（入れてはいけないものが混ざらないように）。試験は隣の `print-craft`（試験用の印刷屋の zip）を使うので、`kintone-plugin/` の下に置く。

```sh
cd ~/Projects/kintone-plugin
git clone https://github.com/rex0220/print-craft-authoring-mcp.git print-craft-authoring-mcp-release
cd print-craft-authoring-mcp-release
git checkout <リリースのコミット>
npm ci
npm run check
npm test
npm run verify:mcpb
CLAUDE=~/.vscode/extensions/anthropic.claude-code-<版>-darwin-arm64/resources/native-binary/claude
"$CLAUDE" plugin validate . && "$CLAUDE" plugin test .
# B2 から: node scripts/build-plugin-zip.mjs && node scripts/plugin-zip-verify.mjs
```

- 成果物の名前をリリースの名前にする: `dist-mcpb/print-craft.mcpb` → `print-craft-authoring-<版>.mcpb`（B2 から `print-craft-plugin-<版>.zip` も）
- sha256 を出す: `shasum -a 256 print-craft-authoring-<版>.mcpb print-craft-plugin-<版>.zip`
- 確かめが済んだら、このフォルダーは消してよい（消す前に成果物を退ける）

- **Desktop**: 候補の `.mcpb` を入れ直し、Claude Desktop を起動し直して、README の Desktop の表を通す（とくに準備の確かめ、アプリ、保存とプレビュー、`main.log` に秘密の値とレコードの値が無いこと）
- **Claude Code**: README の Claude Code の表を通す。B2 からは、プラグインの zip を展開したフォルダーを `--plugin-dir` で読み込んで確かめる（zip の中身だけで動くか。marketplace の archive は https の URL しか受け付けないので、marketplace から入れる形は公開の後に 4-5 で確かめる）
- **Windows**（B3 の前に 1 回。その後は大きな変更のとき）
- 結果を README の表に書く

## 4. 外に出す（各段で Takashi に確認）

1. **main に入れて push**（リリースのコミット）
2. **タグ**: `git tag -a v<版> -m "print-craft MCP <版>"` → `git push origin v<版>`
3. **GitHub のリリース**:
   ```sh
   gh release create v<版> print-craft-authoring-<版>.mcpb print-craft-plugin-<版>.zip \
     --title "print-craft MCP <版>" --notes-file <ノートのファイル>
   ```
   ノートに書くもの: `CHANGELOG.md` の版の節、各ファイルの sha256、要る Claude Desktop と Claude Code の版、中核の版、入れ方（Desktop はダブルクリック、Claude Code は `/plugin marketplace add rex0220/print-craft-authoring-mcp` → `/plugin install print-craft@rex0220-print-craft`）
4. **（B2 から）marketplace を新しい版に**: `.claude-plugin/marketplace.json` の archive の `url` と `sha256` を書き換えて、main に push。**リリースにファイルを置いてから**書き換える（逆だと、入れられない時間ができる）
5. **公開したものを確かめる**: リリースからダウンロードしたファイルの sha256 が手元と同じか。Desktop で `.mcpb` を入れて、版が新しいか（`pcraft_status`）。Claude Code で `/plugin marketplace update rex0220-print-craft` → `/plugin install print-craft@rex0220-print-craft`、版が新しいか、`/config` で zip と接続のファイルを設定できるか（初めての公開のときは、marketplace から入れる形を README の Claude Code の表で一通り）

## 6. まずかったとき

- **配布物に誤り**: `marketplace.json` を前の版の `url` と `sha256` に戻して push する（Claude Code）。GitHub のリリースは pre-release にするか、ファイルを外す（消すのは確認）。直した版を patch で出す
- **秘密の値やレコードの値が配布物に入った**: すぐにファイルを外し、該当するトークン・パスワードを無効にする。Qiita などに上げた画像も同じ（記事から外しても、画像の URL は残る）
- **中核（npm）の誤り**: npm は同じ版を上げ直せない。直した版（patch）を公開し、MCP の依存を上げて MCP も出し直す
